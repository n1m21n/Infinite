## Repro

1. Write a patch with an audio lane whose gain is large, e.g. `stream 1 0 1 100 0 1 0 Lane`, and a `cliptick` on that lane sourcing an audio node. Or put the large value in the cliptick's gain field instead.
2. Run `Infinite --audio-summary p.inf out.json --duration 2 --timeline`, or open the patch and play the arrangement.

## Expected

The gain is held to the fader's range (-60..+12 dB), as pan, opacity and pitch already are on load.

## Actual

- Patch.cpp only replaces a non-finite gainDb with 0 (stream line, `cliptick`, legacy `clip`), and Arrange::Normalize does the same for clips. Every sibling field is clamped.
- AudioTopology.cpp turns it into `pow(10, gainDb / 20)` for the lane (line 377) and the clip (line 408).
- Lane gain 100 dB: sample peak 51,548 (+94 dBFS). Lane gain 1000 dB or 1e30: the gain is inf, the summary reports peak/RMS as null and the bogus "silent" warning, and the live device would get non-finite samples. Clip gain 1000 dB does the same.

## Fix note

The gain is clamped to -60..12 dB, the range of the lane knob and fader, the clip gain slider and the track gain slider. It is applied at the three parse sites and in Arrange::Normalize. The fix was checked against the ASan build from the base branch, with the same patch and the same flags:

| Gain | Base peak | Fix peak |
|---|---|---|
| lane 0 dB | 0.515 | 0.515 |
| lane 12 dB | 2.05 | 2.05 |
| lane 100 dB | 51,548 | 2.05 |
| lane 1000 dB, lane 1e30 | null (inf) | 2.05 |
| clip 1000 dB | null (inf) | 2.05 |

Values in range are unchanged. A hand-written gain below -60 dB now plays at -60 dB, which is inaudible in practice.
