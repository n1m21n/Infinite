## Repro

1. On Windows or Linux, load any AIFF (for example `afconvert -f AIFF -d BEI16@44100 in.wav out.aif`) into a sampler or Audio File node. macOS decodes through AVFoundation and is not affected: it reads the rate correctly, and for the huge FLAC its AVAudioPCMBuffer init returns nil, so the file is refused cleanly (checked with the same calls in a scratch harness).
2. For the allocation: an AIFF whose COMM chunk claims 0xFFFFFFFF frames (62 bytes in all), or a FLAC whose STREAMINFO claims 2^36-1 frames (90 bytes).

## Expected

The file plays at its own rate. 8-bit AIFF plays as recorded. A damaged header gives a short buffer or a refusal.

## Actual

- **Sample rate:** ReadIeeeExtended80 (MediaDecodePortable.cpp:658) divides the 64-bit mantissa by 2^52 instead of 2^63. A 44100 Hz file reports 90,316,800 Hz, and a 48000 Hz file reports 98,304,000 Hz.
- **8-bit sign:** 8-bit samples are decoded as unsigned (`s[0] / 128 - 1`). AIFF is two's-complement at every depth, so the waveform is shifted by full scale.
- **Rate check:** a non-finite rate (exponent 0x7FFF) passes the `rate <= 0.0` check.
- **Allocations:**
  - DecodeAiff allocates `frames * channels` floats and bytes from COMM before reading: 32 GB for the 62-byte file.
  - The FLAC path allocates STREAMINFO's total up front: 512 GB.
  - Under ASan both are allocation-size-too-big. In a normal build Windows throws bad_alloc, and Linux tries to zero-fill tens of GB.
- **Unknown-length FLAC:** a FLAC whose STREAMINFO total is 0 ("unknown", as a FLAC written to a pipe has) is refused as "file contains no audio".

## Fix note

Verified 2026-10-22 by compiling the file on macOS into an ASan harness, base against fix:

| File | Base | Fix |
|---|---|---|
| afconvert 16-bit and 8-bit AIFF | 9.03e7 Hz | 44100 Hz; samples match the source WAV (8-bit within quantization) |
| Crafted 8-bit `00 7F 80 FF` | -1, -0.008, 0, 0.99 | 0, 0.99, -1, -0.008 |
| Infinite-rate AIFF | rate inf | refused |
| Huge-count AIFF | allocation-size-too-big | its 2 real frames |
| Huge-count FLAC | allocation-size-too-big | refused as no audio |
| ffmpeg stereo, mono and piped FLAC | piped refused | all three decode; same samples as before |
| Huge `data` WAV | already clamped by dr_wav | unchanged |

Not built or run on Windows or Linux (that is P5, and needs the owner's go).
