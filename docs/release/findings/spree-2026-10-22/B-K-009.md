## Repro

1. Write a patch with `cable out 0 n 2147483647`, where `n` is any image source and `out` is an Output.
2. Open it in the GUI (or run with INFINITE_LOADPATCH and INFINITE_EXITAFTER=90).

## Expected

The bad link is dropped, and the rest of the patch loads.

## Actual

- ApplyPatchData (PatchLoad.cpp) and the deferred mod pass (PatchFiles.cpp) pass the file's srcOutput straight to Connect, ConnectGeometrySlot and RestoreLink. Only the headless validator (PatchSchema) checks it.
- The editor builds the cable's start pin with `GraphNode::OutputPinId(output) = index * 1050 + 990 + output` (GraphNode.h:121). The pin block holds outputs 0..59.
- With 2147483647, that addition overflows int. Under UBSan this is a "signed integer overflow" abort on the first frame (rc 134). In a release build it is undefined behaviour; in practice the pin id wraps to a meaningless number.
- With 60, the pin id is the next node's NodeId. With -5, it lands in this node's colour-pin block. In both cases the cable is wired in the engine but drawn to the wrong place, or not drawn at all.
- The engine side is already safe: AudioBufferIndexOf clamps, the Note Router clamps, and GetOutputTexture returns 0 for an unknown index.

## Fix note

A file-local check (0 <= output < kStride - kOutputBase) is applied to every cable, geo, aud, note and mod link in ApplyPatchData, and to the mod links in the deferred keyed pass. A link that fails is skipped like one whose node is missing. Cluster copy/paste rebuilds its links from live cables, so it never sees a bad index.
