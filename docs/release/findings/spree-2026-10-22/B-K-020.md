## Repro

On Windows or Linux, load any of these as a .wav (drag into a sampler or looper, import to the arrangement, or put it in a scanned sample folder):
- A 58-byte AIFF named .wav with an `SSND` chunk of size 0.
- A W64 file with an unknown chunk claiming size 0xFFFFFFFFFFFFFF00.

## Expected

The decode fails with "not a readable WAV file".

## Actual

The decode never returns, and one core stays at 100%.
- dr_wav steps over chunks it does not use by calling `drwav__seek_forward(size)` in 0x7FFFFFFF steps.
- For SSND it first does `chunkSize -= 8`. That wraps when the chunk is under 8 bytes (dr_wav.h:3711). It is still unguarded in upstream dr_wav 0.14.6 master.
- A W64 chunk size is 64-bit, so it can be ~2^64 outright.
- stdio `fseek` succeeds past EOF, so about 2^33 seeks all succeed.

The decode runs on the main thread for file loads and on the scanner thread for library scans. macOS decodes through AVFoundation and is not affected.

## Fix note

- `MediaDecodePortable.cpp` now opens the file itself and passes read/seek/tell callbacks to `drwav_init`. The seek callback refuses any target past the end of the file, so a bad size fails the open on its first step. This covers every chunk type, not just SSND.
- dr_wav itself is unpatched, so it can still be upgraded as-is.
- The 64-bit tell/seek (`_ftelli64` / `ftello`) keeps RF64 files over 2 GB working.
