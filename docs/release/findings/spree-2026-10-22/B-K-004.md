## Repro

1. A 24-byte file: an 8-byte `free` atom, then an atom with size field 1 (64-bit form) and a 64-bit size of 2^64-8.
2. Open it in a Video Source node. Any movie goes through Hap::Reader::Probe first, not only HAP files.

## Expected

The file is refused as not a HAP movie.

## Actual

LoadMovie (HapReader.cpp:232) checks `pos + size > fileSize`. The sum wraps to 0, so the check passes and `pos += size` sends pos back to 0: an endless loop on the thread that opens the movie. NextAtom (:54) has the same check, so the same atom inside `moov` loops in the trak scan, and a wrapped atom's end < body would also defeat ParseTrak's `end - body` length checks. A harness on the base code hangs on both files (killed by an alarm after 3 s).

## Fix note
Verified 2026-10-22: both checks now compare the size against what is left (`size > end - pos`), which cannot wrap because `pos + 8 <= end` is already checked. The harness refuses both files at once, and the B-K-003 harness cases still pass. In-app COMPAUDIT on the branch: every HAP case passes (file probe and open, raw, snappy and chunked frames with matching bytes, cut-off file refused, both nodes shown); the only flags are the two known Fluid ones.
