## Repro

Any patch line `f <param> 1e30` (or -1e30) on a node whose param is an enum, count, size or seed stored as a float. For example, an Audio Filter, EQ, Delay, Chorus, Particle System, Render 3D, Fit, Reaction Diffusion or any color filter. The patch can come from a file, a paste, or an OSC/RPC set.

## Expected

The value is rejected or clamped, and the node uses a valid value.

## Actual

`(int)(v + 0.5f)` on a float past ±2³¹ is undefined behaviour. UBSan aborts at the first one per patch:

- FxBodies1/2: about 15 sites, enum reads for status text and visualizers.
- GeometryParams:2211: geometry-op dropdowns.
- FilterNode:246: enum shader uniforms.
- EqKernel.h:54: band type, on the audio thread.
- Geometry3DNodes:1598: Render 3D width/height.
- FitNode:66.
- FeedbackNodes:348: Reaction Diffusion steps.
- SimulationNodes:62: Particle System seed, cast to `unsigned`. This one is also UB for any negative seed.
- NoteNodes: Arpeggiator, Chorder, Gate, Humanizer and others. A note length in samples, built from hold ms, gate %, step rate or swing, is cast to `uint64_t`. That overflows on a product of two large params, and it's UB for a negative length (Chorder's `lengthSteps - 0.15` at 0).

On release builds the result is whatever the CPU makes of it. On arm64 that's a saturated int, usually harmless but not defined.

`Field::Rand`/`Sh` had the same bug: `(int64_t)seed`, where an expression can pass NaN or 1e30.

## Fix note

Every runtime writer already clamps to the param's range: sliders, typed values (ModWidgets:275), modulation and expressions (`ShapeToParam`). Only `Patch::LoadParams` could deliver an unbounded float. It already dropped non-finite values as a missing key; it now drops |v| ≥ 2³¹ the same way. That fixes every site above at once. A per-site clamp would be 20+ edits, and each UBSan run only shows the first.

Also:
- The reader's `Int` uses strtoll and saturates. `atoi` overflow was UB.
- Particle seed: `fmod(|seed| * 1000, 2^32)`. Same stream for every non-negative seed below 4.29M.
- `Field` seeds: `fmod(seed, 9e18)`, with non-finite mapping to 0.
- GeometryTable: it takes `offset`'s fraction before `offset * count`. Same row after the modulo.
- Humanizer: the timing jitter is clamped to ±block before the cast. The next line clamps to the block anyway.
- NoteNodes: a `SampleCount()` helper saturates to [0, 4e18]. It's used at the 12 param-derived casts, because the load bound alone can't stop a product of two 2e9 params. In-range behaviour is unchanged: every length is non-negative, and groove is 0..1.

Values that fit in an int but sit outside the declared range (a width of 1e9, an enum of 1000000) aren't covered here. The float sweep now also tries 1e9 and -1 for those.
