## Repro

1. On Windows, start the app with INFINITE_COMPAUDIT=1 (or another INFINITE_* self-test var) set and use Share > frame/render.
2. Frequency: always on Windows.

## Expected

The child `--frame` / `--render` process runs clean, without the parent's self-test env vars.

## Actual

PatchShare.cpp RunSelf strips four INFINITE_* vars on POSIX only and none on Windows; the strip list also misses every other INFINITE_*TEST var.

## Notes

## Fix note
Wider than reported. It wasn't only Windows: about 40 self-test switches are dispatched before the headless args are parsed (Startup.cpp:343-613 vs :788). So any switch other than the four stripped names also hijacked the child on macOS, e.g. `INFINITE_DSPTEST=1 Infinite --frame ...` prints "DSPTEST OK". The fix uses an allow-list of config vars, shared by share and CompAudit's --validate relaunch (which was POSIX-only). The Windows `set "X="&` prefix needs a Windows build and a run before this can be marked verified.
