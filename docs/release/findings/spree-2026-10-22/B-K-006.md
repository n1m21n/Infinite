## Repro

1. An ASCII PLY with 3 vertices and one face `3 0 1 4000000`.
2. Load it in a Model node on Windows or Linux. macOS goes through ModelIO, so it is not affected.

## Expected

The file is refused as damaged.

## Actual

LoadModelPly (MediaDecodePortable.cpp:577-600 for ASCII, and the binary face path) pushes face indices with strtoul and no range check. FinishModel (:155) then runs GenerateNormals, which writes through `vertices[indices[i]]` (ASan BUS at :122). A file that has its own normals skips that step, and the bad index goes to the renderer instead.

## Fix note
Verified 2026-10-22 with the file compiled on macOS into an ASan harness (strtok_s mapped to strtok_r): the bad PLY is refused, while a good PLY and good and bad OBJ files load as before (OBJ already drops out-of-range indices). FinishModel is the one exit of the OBJ, STL and PLY loaders. Not built or run on Windows or Linux (that is P5, and needs the owner's go).
