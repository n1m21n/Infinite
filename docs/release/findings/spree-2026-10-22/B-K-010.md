## Repro

1. Write a patch with LFO, Noise and Output, `cable out 0 n 0`, and `mod n width lfo 0 0 1 0 -3e38 3e38 1 100 0`. That is lo -3e38, hi 3e38 and curve 100. All values are finite, and the load path stores them as they are.
2. Run `Infinite --frame p.inf 1.0 out.png`, or open it in the GUI.

## Expected

The param stays inside its declared range, as ShapeToParam's comment promises ("a hard contract ... everything downstream ... does not re-check it").

## Actual

- ApplyModulationCurve is `pow(v, exp2(curve * 3))`. With curve 100 the exponent is inf, so v < 1 shapes to exactly 0.
- The apply loop writes `lo + (hi - lo) * v01`. Here hi - lo overflows to inf, and inf * 0 is NaN.
- ShapeToParam (MiscTests.cpp:2451) is `std::clamp(v, min, max)`, which returns NaN unchanged.
- On `width`, NoiseNode::CookIfNeeded (NoiseNode.cpp:189) casts it to int. UBSan reports "nan is outside the range of representable values of type 'int'" and aborts (rc 134). In a release build that is undefined behaviour, used as a texture size.
- On `seed`, the frame renders black (W_BLACK_FRAME).
- Modulation::SetCurve clamps a curve to [-1, 1], but RestoreLink (the load path) does not. The fix does not depend on that.

## Fix note

ShapeToParam now replaces NaN with the param's current value, or with its min if that is not finite either, before it snaps and clamps. The same guard covers expressions and perf controls, which go through the same function.

|---|---|---|
| width | NaN-to-int runtime error, abort | rc 0, no reports |
| seed | W_BLACK_FRAME | rc 0, no warnings |
| octaves, noiseType | rc 0 | rc 0 |
| sane mod (lo 1, hi 2) | - | rc 0 |
