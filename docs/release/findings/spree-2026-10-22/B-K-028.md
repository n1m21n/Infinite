## Repro

Feed a NaN or inf block into Wavetable Shaper: a VST, a damaged file played with `INFINITE_DECODE_KEEP_NONFINITE`, or a NaN-producing upstream node. On an ASan+UBSan build, DSPTEST aborts with `nan is outside the range of representable values of type 'int'` at `Wavetable.h:96`.

## Expected

NaN only for that block (B-K-023 resets the kernel afterwards), with nothing undefined while it happens.

## Actual

The input goes through the oversampler into `ReadPhase`, giving a NaN phase and slew mip. `Wavetable::Sample` does `(int)(phase * kFrameSize)`, and `ReadAtMip` does `(int)mipPos` after a `std::clamp` that passes NaN on. Both are undefined.

On arm64 release builds the conversion yields 0, so it hasn't been seen to misbehave. The behaviour is still undefined, and it's a cast plus a table index on the audio thread.

B-K-023's guard runs after the kernel, so it can't prevent this.

## Fix note

- `Wavetable::Sample` reads position 0 for a non-finite phase. It's also used by WavetableSynthCore, where finite phases are unchanged.
- `ReadAtMip` maps a NaN phase, mip or position to 0 before its clamps and casts.

Why it was missed: DSPTEST had only run on release builds. The selftests should run under the sanitizer build too (`tools/bughunt` README).
