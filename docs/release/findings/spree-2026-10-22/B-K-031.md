## Repro

Load a patch with a Stereo node set to `f width 1e9`, or set it by OSC or RPC. Feed it any stereo audio that isn't pure mono.

## Expected

The width is held to its 0..2 range, as the knob does.

## Actual

The side signal is scaled by 1e9, so the output is around 1e8 (HOTAUDIO). B-K-026 drops values at or beyond 2^31, but 1e9 is a valid float inside that limit, so it passes. `Patch::LoadParams` → `AudioEffectNode::VisitParams` stores it with no range check. The float re-sweep found two more cases on the verify build:
- EQ 1e9 → HOTAUDIO.
- Flanger 1e9 aborts under UBSan. `DrawFlangerVisualizer` (FxBodies2.cpp:207) strokes a path built from the 1e9 param, and imgui casts a 2.2e9 coordinate to int (imgui_draw.cpp:840).

The same path is open for all 28 `EffectDef` types: file load, OSC (`OscApi.cpp`), RPC (`Rpc.cpp`), clipboard and presets all go through `Patch::LoadParams`.

## Fix note

`AudioEffectNode::VisitParams` clamps `mix` to 0..1 and every param to its def's `minVal..maxVal`. Every route above goes through it.

Blast-radius checks before the fix:
- **UI ranges:** for all 141 ranged params (describe.json), the UI range is never wider than the def's. The clamp can't change a value the knob could set.
- **Defaults and sweep values:** no def default, sweep prerequisite or test candidate sits outside its own range.
