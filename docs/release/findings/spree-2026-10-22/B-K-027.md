## Repro

1. A Palette node fed by any image, with the seed slider (0..64) set to 2.
2. Note the swatches, then set seed to 5, 20 or 64.

## Expected

"Same seed, same palette" (the param's own comment), and a different seed gives a different k-means++ start.

## Actual

`Rng rng((unsigned int)(std::fabs(seed) * 2654435761.0f) + 1u);` passes 2³² once seed ≥ 1.62. The float→unsigned cast is then undefined. On arm64 it saturates to 0xFFFFFFFF, and `+ 1u` wraps that to 0. `Rng` maps 0 to a fixed constant, so every seed from about 1.62 to 64 starts k-means++ from the same state and gives the same palette. That's 97% of the slider. UBSan flagged it from the float sweep.

## Fix note

Wrap the product mod 2³² in double precision, and map a non-finite seed to 0. Seeds below 1.62 keep their exact old stream, so existing patches in that range don't change. Seeds above it now differ from each other; before, they were all one palette.
