## Repro

1. Load any patch with a PaulStretch node, or open `int-PaulStretch-base.inf` under the ASan build: stack-use-after-scope READ in ApplyModulationAndPalette (CookFrame.cpp:200).
2. Bind an LFO to PaulStretch `unison`: each frame, Modulation writes the LFO value through the pointer. Grain Molder `seed` is not in the patch-file modulation list, so it is reached only through MIDI learn, OSC or perf.

## Expected

A registered control points at the node's own member, or at the persistent int shadow (`gIntParamStore`) that every other int control uses.

## Actual

- **The cause:** both bodies do `float x = (float)n->member; AudioSlider("...", &x, ...)`. AudioSlider registers `&x` as `ParamRef::value`, and `x` is dead by the time anything uses it.
- **Reads:** the next frame's parameter snapshot reads through `&x` (CookFrame.cpp:200), and so does `--describe`'s Tier1 baseline (Headless.cpp:445).
- **Writes:** when the control is modulated, MIDI-learned, or driven by OSC or perf, `*ref.value = ...` writes into whatever the stack holds at that address. That is silent stack corruption in the GUI app, and the modulation never reaches the node.

## Fix note

- **Both sites:** they now use `AudioSliderInt(&n->member)`. It registers a persistent float shadow and takes one param index, as before, so saved modulation bindings keep their slot.
- **Visible change:** the unison readout drops its " v" suffix.
- **Blast radius:** a scan of `src/app` for every Mod or Audio slider, knob or fader whose value is `&local` (or `&local.field`) found only these two. KnobFloat and AudioSliderFloat calls on locals are raw widgets that do not register.
