## Fix note
Test-only bug. A per-frame trace on a failing run showed the stable-frame count building up while scan=1 (index v2). When the scan finished, the guard passed at once; the panel then polled v3, and the row moved from y 296-320 to 276-300. The press at y=308 hit the list well, not the row. The fix counts only idle-scanner frames, keyed on id, index version and rect, and re-aims in phase 1. Load (10 `yes` loops) reproduces it reliably, which is why batch runs failed and lone runs didn't. The Sampler and Media drag tests have no scanner, so they don't share this race.
