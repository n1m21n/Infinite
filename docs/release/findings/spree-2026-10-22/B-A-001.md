## Repro

1. Run a headless job whose single tick blocks (e.g. a render that hangs inside one frame, as on Windows x64 CI in B-J-001) with `--timeout 60`.
2. Frequency: whenever one tick blocks.

## Expected

`--timeout` kills the job at the deadline and reports E_TIMEOUT.

## Actual

Headless.cpp:782 only compares wall time between ticks, so a blocked tick runs forever; RunSelf (PatchShare.cpp:47-63) adds no outer timeout around std::system either.

## Notes

## Fix note
A watchdog thread fires 5 s past --timeout. With no status out it reports E_TIMEOUT and exits 6; with a status out but the process stuck in teardown it exits with that code. This may also cover the Windows CI hang (B-J-001) if that hang is in teardown, but that is unverified here.
