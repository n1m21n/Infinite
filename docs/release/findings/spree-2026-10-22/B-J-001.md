Spree 2026-10-22, code-only pass from macOS (status unchanged; needs P5):
- The CI job `--frame tests/render/audio.inf 0,1 <dir> --lenient` finishes in under 1 s on macOS arm64 with ok:true. The hang is specific to Windows x64, since ARM64 passes.
- By design, a headless job never opens an audio device (ArrangeRender.cpp:56, gated on gHeadlessAudioRate), so a WASAPI open on a runner with no audio endpoint isn't the obvious path. Still worth checking on the box, along with COM init (AudioDeviceWin.cpp:154) if any enumeration runs at startup.
- bugfix/headless-hard-timeout (B-A-001) turns a frame that never returns into exit 6 with an E_TIMEOUT status. CI's 300 s limit is below the default --timeout of 600 s, though. Passing `--timeout 120` in build.yml would make the hang report itself instead of being killed silently. If the hang is in teardown after the status is printed, the watchdog exits with that status's code instead.
