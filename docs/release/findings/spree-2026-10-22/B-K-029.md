## Repro

A patch has a Molder node with an audio file and `i generation 2147483647`. A remote param set can deliver the same value. Open the patch.

## Expected

It loads at once.

## Actual

`BuildDesiredGenome` replays one `Mutate` per generation, and it runs on the main thread inside `LaunchJob`. One `Mutate` takes about 0.2 µs on a release build (timed standalone: 1e6 calls in 0.200 s). So 2^31 generations block the UI for about 7 minutes, and longer under ASan. This repeats on every knob change that re-dispatches the render.

The int sweep marked Molder "ok" at 2147483647 because its rows had no audio file. Without a file the analysis is never valid and the loop never runs.

## Fix note

The generation is clamped to `MolderNode::kMaxGeneration` (10000, about 2 ms):
- in `VisitParams` after the read;
- at the loop, which covers retaining visitors that write the member directly;
- in `Roll`, which also makes `++` safe from overflow.

Each `Mutate` pulls the genome 10% back toward the baseline, so nothing from before the last few hundred rolls survives. No reachable sound changes, since no one clicks Roll 10000 times.

## Tooling gap

The int and float sweeps run each node with no stimulus. File players, note processors and anything gated on analysis never reach their per-item loops. See the README's note on the stimulus per kind.
