## Repro

1. A patch with `perfui 76 2000000000` (or a `perf` line with cellX 2000000000).
2. Open it and show the performance matrix.

## Expected

The panel opens; a hostile or corrupt value is clamped on load.

## Actual

Patch.cpp:808 reads pageCount with no upper bound; PatchLoad.cpp:307 only fixes values below 1. DrawPerfPanelContent (PerfPanel.cpp:2117) then pushes one "Page N" string per page (2e9 strings, tens of GB) and the tab loop at :2216 runs pageCount times per frame. A huge element cellX/cellY drives maxElemX, so numCols/numRows at :2358 become billions of AddLine calls per frame. Headless runs never draw the panel, so `--frame` on the crafted patch exits 0 (checked); the hang is GUI-only. Not run in the GUI on purpose: it would exhaust memory on the dev Mac.

## Fix note
Verified 2026-10-22: ApplyPatchData clamps pageCount to 1..12, cellSize to 40..400 (else 76) and element cells to 0..512. The new PERFBOUNDSTEST loads `perfui 76 2000000000` plus a perf element at cell 2e9, draws the panel and passes. PERFMATRIXTEST passes too.
