## Repro

1. Build with `-DINFINITE_SANITIZE=address,undefined`.
2. `Infinite --validate <patch with one PaulStretch node>` (or `--frame tests/headless/patch_video.inf 1.0 x.png`).
3. ASan: `stack-use-after-scope` READ of size 4 in `ParamKeyJoiner::Tier1` (Headless.cpp:445) or `ApplyModulationAndPalette` (CookFrame.cpp:200).

## Expected

Every ParamRef registered with Modulation points at storage that outlives the frame.

## Actual

`DrawPaulStretchBody` (SamplerBodies.cpp:737) draws `unison` on `float unisonF = (float)n->unison;`, and `DrawGrainMolderBody` (:1265) draws `seed` on `float seedFloat`. AudioSlider -> ModSlider registers `&unisonF` in FrameParams. Next frame, ApplyModulationAndPalette snapshots `*ref.value` from that dead address (the read ASan caught). The write path is worse: a modulation, perf element or MIDI binding on unison/seed makes CookFrame.cpp:185 do `*ref.value = ShapeToParam(...)`, a 4-byte write into whatever stack frame now holds that address. In release builds it is silent stack corruption, and the binding never reaches the node.

In the smoke run, 19 of its sanitizer reports were this one bug: 16 in the validate/describe join and 3 in frame cooking. That made 33 smoke checks fail under ASan.

## Blast radius

1. Callers: AudioSliderInt/ModSliderInt gain an optional trailing `fmt` (default "%.0f", the old literal); no existing call changes.
2. Param ordinals: ModSliderInt calls ModSlider once, as AudioSlider did, so paramIndex for unison/seed and everything after them is unchanged; saved bindings keep their targets.
3. Values: unison was already clamped 1..8 and rounded; seed now rounds (was truncation) and is clamped 1..9999 on draw, like every other int slider (a patch-file seed outside 1..9999 is pulled in when the node draws; --validate already reports such a value as out of range).
4. Undo: ModSlider pushes its own checkpoint on activation; the seed branch's extra per-change PushUndoCheckpoint is gone (it pushed one per drag frame).
5. Describe join: srcAddr is now &n->unison / &n->seed, so both keys join on address (Tier 1) instead of falling to label matching.
6. Audio thread: untouched; the nodes read their int members as before.
7. Other sites: grep of every ModSlider/ModKnob/AudioSlider call with a bare `&identifier` found only these two (AudioNodeBodies `fine` is a reference into the node; `sUnassigned` is static).
8. Platforms: shared code, no platform branches.
9. Tests: ASan smoke re-run on the fixed branch.
