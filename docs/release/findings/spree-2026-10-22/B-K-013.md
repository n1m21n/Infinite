## Repro

1. Write a patch with a Field node (or Sketch / Sketch 3D) whose params contain `i field_nextParamId 2147483647`, or a `s field_paramMap` entry with a large id such as `freq:5000`.
2. Load it and add a `param float` line to the code, or open the fuzz case `int-Sketch_3D-2147483647.inf` under the sanitizer build.

## Expected

Ids stay inside the node's param pin block (pin index 50 + id < 800) and never collide.

## Actual

- **Overflow:** the new param gets id 2147483647. The next one overflows `mNextParamId++` (UBSan at ParamTable.cpp:126).
- **Wrong pins:** pin index 50 + id runs past the node's param block. Ids 750–789 sit on colour pins, 790 and up on output pins, and larger ids reach other nodes' pins (pin id = node * 1050 + 100 + index).
- **Duplicates:** a map that gives two names the same id is accepted.

## Fix note

`kMaxParamId = 749`.
- **Loading the map:** entries outside 1..749, or reusing another name's id, are dropped.
- **Loading the counter:** an out-of-range `field_nextParamId` restarts at 1.
- **New ids:** `AllocateId` skips any id that is in use. Once 749 is used up, it takes the lowest id no declared param holds. FieldIR's 128-param cap means that path is never exhausted.

Ordinary patches never reach these values: ids only grow by one for each param name a node has ever had.
