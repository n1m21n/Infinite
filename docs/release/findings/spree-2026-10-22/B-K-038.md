## Repro

```
infinite-patch 1
node 1 Source Text
  f width 1e9
end
node 101 Utility Output
end
cable 101 0 1
```

`Infinite --frame text-1e9.inf 0.5 out.png`

## Expected

Each size is held to a side the GPU and memory can take. Every pixel-size knob tops out at 8192 or below.

## Actual

| Nodes | Size math | Result at width 1e9 |
|---|---|---|
| Text | `mPixels.assign(w*h*4)` | Asks for 4 TB on the CPU. ASan aborts (exit 134); release throws `bad_alloc`, and the app quits. |
| Render 3D (and its post pass), Fit | GL targets | The target fails and the render reports E_RENDER. Sides of 8192 to 16384 are valid GL but ask for gigabytes. |
| Ramp, Slideshow, FieldPixel, Noise, Formula, Shape, Feedback, Texture | GL targets | Same as Render 3D. |

Every one used `std::max(lo, (int)width)`, a floor with no cap. `Patch::LoadParams` passes any finite float under 2^31.

## Fix note

`GLUtil::TargetSide(v, lo)` returns a value in lo..8192 and maps NaN to lo. All 13 sites use it. Sketch already capped at 4096.

Blast radius:
- **Saved patches:** `clamp_check.py`, with the canary `Type.width=0..1` hitting, found 0 saved values outside 1..8192 for any of these types. Slideshow and Texture appear in no tracked patch.
- **Writers in code:** only perf selftests, and their sizes stay at 8K or below.

## Lesson

A lead logged as "E_RENDER, S4" was the mild member of a family. The same `max(lo, (int)width)` on a CPU buffer was an abort. When a lead is a pattern, grep the pattern before rating it.
