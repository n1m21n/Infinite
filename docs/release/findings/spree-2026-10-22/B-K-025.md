## Repro

1. Load a sample into Molder and Roll a few times until it sounds right (say generation 4).
2. Save the patch and reopen it. Or: copy and paste the node, or change any param and press undo.

## Expected

The same sound: the patch saved `seed` and `generation`, and Molder rebuilds the genome from exactly those two.

## Actual

The sound is different every time. Patch load, paste, undo/redo and multi-node delete all respawn the node from its params and then call `ReloadDerivedState` → `MolderNode::ReloadFromPath` → `LoadFile`. `LoadFile` treated every call as a brand-new source. It overwrote the restored `mSeed` with `std::random_device` and set `mGeneration = 0` before dispatching the render. The saved values were read, then thrown away.

MOLDERTEST's save/load check only compared params after `LoadParams` and never called `ReloadFromPath`, so it passed.

This is also why headless `--audio-summary` renders of a Molder patch differed run to run.

## Fix note

`LoadFile(path, keepGenome = false)`. A fresh load (drop, browse, sample drag) still rolls a new seed and starts at generation 0. `ReloadFromPath()` passes `keepGenome = true`, so the restored seed and generation drive the render. MOLDERTEST now respawns a node with seed 12345 at generation 4, reloads it, and checks both survive. It also checks that a fresh `LoadFile` still resets the generation.

Blast radius: `LoadFile` has two other callers, StageDropHandling:269 (file drop) and StagePopupsA:994 (sample drag). Both are new sources and keep the old roll by default. Typing a new `path` in the inspector goes through ParamBodies1:33 → `ReloadDerivedState`, so it now keeps the current seed and generation for the new file. That's acceptable, because both are visible params next to it. GrainMolder has no seed. The only other `random_device` in src/nodes is FieldGraphNode's, which only makes UIDs and doesn't touch audio.
