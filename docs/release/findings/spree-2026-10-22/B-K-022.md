## Repro

On Windows or Linux, load a 59-byte file named .wav that is really an AIFF. Its COMM chunk claims 0xFF000004 sample frames, and its SSND chunk holds 4 bytes. Load it by dragging it into a sampler or looper, importing it to the arrangement, or putting it in a scanned sample folder.

## Expected

The 2 real frames decode, or the file is refused.

## Actual

`DecodeAudioFileToBuffer` allocates `totalPCMFrameCount x channels` floats before reading. That is about 34 GB, zero-filled on the loading thread, so the app stalls for minutes or is killed for running out of memory. The allocation also happens for a file it is about to refuse for having more than 2 channels. macOS decodes through AVFoundation and is not affected.

## Fix note

The WAV path now decodes in 4096-frame chunks until dr_wav runs out, exactly as the MP3 and FLAC paths next to it already did, with the same INT_MAX frame cap. A file with more than 2 channels allocates nothing.
