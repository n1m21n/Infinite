# Все цвета темы в одном JSON: исследование

Дата: 2026-11-12. Продолжение темы B из `agents-and-themes.md`. Чтение кода, ничего не собиралось и не запускалось —
поведение в рантайме **не проверено**. Решение владельца: не вводить «второй/третий тёмный», а вынести все цвета в
редактируемый JSON. Работа для личного форка (паритет ОС и переводы на 5 языков не обязательны).

## 1. tokens.json и build_tokens.py

**Структура** `src/app/ui/design/tokens.json` (5716 строк только из-за того, что каждый массив RGBA печатается по числу на строку):

| Секция | Что внутри | Штук |
|---|---|---|
| `base` (`tokens.json:3`) | `space` 5, `radius` 5, `type` 4, `motion_ms` 9, `hit_min`/`bar_h`/`tile`, `icon` 3, `pin` 6 (радиусы) | ~35 чисел, **не цвета** |
| `roles.pairs` | роли с парой `[dark, light]`, RGBA 0-255 (`scope.*`, `backdrop.*`, `curvebox.*`, `curve.*`, `pin.*`, `action.*`, `terminal.*` с ansi0..15, `badge.favorite`) | 59 |
| `roles.pairs_f` | то же, но float 0-1 (`dropdown.fill`, `dropdown.hover`…) | 4 |
| `roles.fixed` | один цвет без пары (`transparent`, `record`, `danger_hover`…) | 8 |
| `roles.accent_ladder` | три коэффициента hover/selected/pressed | 3 (числа) |
| `palette` | **значения-литералы с именем по hex**: `c_6ED78CFF` | 653 |
| `palette_f` | то же во float: `v_550_380_100_1000` | 133 |

Итого цветов ≈ **857** (59+4+8+653+133), из них только 71 именованные роли; **786 — «палитра» с именами по значению**,
т.е. прошлый перевод литералов на токены (см. §4) шёл механически: имя токена не говорит, что это за цвет.
Для темизации это главная проблема: `c_3B82F6FF` может использоваться в десяти несвязанных местах.

**Генератор** `tools/design/build_tokens.py:11-47`: пишет `Tokens.gen.h` (914 строк) в `namespace tok`:
- размеры — `constexpr float space_1 = 4.0f;` (:16-23);
- пары — `constexpr Pair8 scope_bg = {{dark},{light}};` (:27-29), `Pairf`, одиночные `Rgba8`;
- `tok::pal::c_XXXXXXXX` и `tok::palf::v_…` — `constexpr Rgba8/Rgbaf` (:34-41).
Точка в имени роли заменяется на `_` (`ident()`, :9). Режим `--check` падает, если заголовок устарел. Описаний у токенов нет —
только поля `_doc` у групп (`tokens.json:2`, `roles._doc`).

**Доступ из кода** (`app/ui/design/TokenColors.h:7-24`): `constexpr ImU32 tok::U32(const Pair8&, bool light)`,
`U32(const Rgba8&)`, `V4(const Rgbaf&)`, `V4(const Pairf&, bool light)`. Строк с `tok::` в `src/` (без `Tokens.gen.h`): **1688**.
Разбивка вхождений: `U32` 692, `V4` 164, `pal::` 605, `palf::` 160, `space_` 470, `radius_` 169, `tile/bar_h/hit_min` 90,
`icon_` 51, `motion_` 40, `pin_` 31. Больше всего в `app/panels/ChatPanel.cpp` (217), `ArrangePanel.cpp` (122),
`ui/ModWidgets.cpp` (105), `bodies/OscBodies.cpp` (81), `NoteBodies.cpp` (60), `frame/StageMenuBar.cpp` (56).
Используется 587 разных `pal`/`palf` значений из 786; именованных ролей через `U32` — 32 разных.

## 2. Можно ли сделать цветовые токены загружаемыми

**Что мешает** (грепом найден один реальный случай, остальное — по структуре кода, не проверено сборкой):
1. Все токены `constexpr` — переопределить нельзя по определению.
2. Единственный `constexpr` от цветового токена: `inline constexpr ImU32 kPredictionPinCol = tok::U32(tok::pal::c_6ED78CFF)` (`app/AppShared.h:2287`). Ломается, станет функцией/inline-переменной.
3. `app/panels/TerminalPanel.cpp:84-91`: `static const tok::Pair8* const kColors[] = {&tok::terminal_ansi0,…}` — массив указателей; **сохранится**, если токены останутся объектами с постоянным адресом (`inline`, не `constexpr`).
4. `constexpr float kPillText = tok::type_body` (`panels/CookOverlay.cpp:111`) — размеры не трогаем, не мешает.
5. `switch`/шаблонов по значению цветового токена не найдено (`grep tok::` по `case`/`template` — не искал отдельно, **не проверено**).
6. Токены читаются каждый кадр в местах отрисовки (`U32(...)` в draw-коде) — значит подмена значения подхватится на следующем кадре без перерисовки структур. Кэшей `static const ImU32 = tok::…` не найдено.

**Минимальный рефактор «сборочные дефолты + JSON-переопределение»:**
- `build_tokens.py` генерирует цветовые токены как `inline Pair8 scope_bg = {...};` (не `constexpr`), плюс
  `inline constexpr Pair8 kDefault_scope_bg` (или один массив дефолтов) и реестр `kRegistry[] = {{"scope.bg", Kind::Pair8, &scope_bg, &default_scope_bg}, …}`.
  `U32`/`V4` остаются `constexpr`-функциями (работают и в рантайме) — **вызовы в 1688 местах не меняются**.
- `kPredictionPinCol` → `inline ImU32 PredictionPinCol()`; 1 место (+ его использования, число не считал).
- Загрузчик: `tok::ResetToDefaults()` (копия дефолтов), затем применение переопределений из JSON по имени из реестра.
- Не-цветовые токены (размеры/моушн) остаются `constexpr` — это сознательно: они нужны в `constexpr float` контекстах, и темой не являются.
- Для 786 хекс-именованных палитровых токенов см. §4: либо переопределение «по хексу» (грубо), либо переименование в роли (L).
- Риск: `inline` (C++17) вместо `constexpr` убирает свёртку констант в горячих циклах — не критично, но производительность **не измерялась**.

## 3. Единая схема JSON темы

Три слоя сводим в один файл, где слои применяются сверху вниз, а всё отсутствующее наследуется от `base`:
1. `colors` — 6 базовых цветов `UiTheme` → из них `ApplyTheme()` (`ui/Theme.cpp:370`) выводит ~61 `ImGuiCol_*`;
2. `categories`, `cables` — 11 цветов категорий и 5 типов кабелей;
3. `tokens` — переопределение любого именованного токена из реестра (имена как в `tokens.json`: `scope.bg`, `terminal.ansi1`, …);
4. `imgui` — переопределение любого `ImGuiCol_*` **после** вывода (имя = `ImGui::GetStyleColorName(i)`, свой список вести не надо);
5. `palette` — грубый переопределитель по хекс-имени (`"6ED78C": "#44CC88"`), аварийный выход для литералов, пока не названы роли.

Правила: цвет — `"#RRGGBB"` или `"#RRGGBBAA"`; токен-пара — строка (применяется к активному режиму) или `{"dark":…, "light":…}`;
`mode` необязателен (`"dark"|"light"`, иначе по яркости `windowBg`, как `IsThemeLight`, `core/CategoryColors.cpp:628`).
Неизвестные ключи — предупреждение, не ошибка. Размеры в схему не входят (при желании — позже секция `metrics`).

**Короткая тема (валидна, всё остальное от `base`):**
```json
{
  "name": "Мой закат",
  "base": "Infinite Ember",
  "colors": {
    "windowBg": "#14111A", "panelBg": "#1C1824", "text": "#EDE6F2",
    "textDim": "#9A90A8", "border": "#3A3347", "accent": "#FF8A4C"
  }
}
```
**Фрагмент полной:**
```json
{
  "name": "Мой закат", "base": "Infinite Ember", "mode": "dark",
  "colors": { "windowBg": "#14111A", "panelBg": "#1C1824", "text": "#EDE6F2",
              "textDim": "#9A90A8", "border": "#3A3347", "accent": "#FF8A4C" },
  "categories": { "Source": "#E06C75", "Effects": "#C678DD", "Modulators": "#56B6C2" },
  "cables": { "Float": "#FFB347" },
  "tokens": {
    "scope.bg": "#0B0C10",
    "pin.idle": { "dark": "#7A8299", "light": "#5A6178" },
    "terminal.ansi1": "#E06C75"
  },
  "imgui": { "Button": "#2A2433", "FrameBg": "#211C2B80" },
  "palette": { "6ED78C": "#44CC88" }
}
```
Размещение: `<SettingsDir>/themes/*.json` (`platform/AppPaths.h:201-262`). Существующие `Infinite.theme` (имя пресета) и
`Infinite.appearance` (`key=r,g,b`, `CategoryColors.cpp:960-1000`) — оставить как есть и применять **поверх** JSON-темы
(обратная совместимость); решить позже, мигрировать ли их в JSON (не проверено, как они сейчас взаимодействуют с `base`).
Выбор темы по имени уже сохраняется (`CategoryColors.cpp:441-452`). Автотесты перебирают пресеты по индексам
(`MiscTests.cpp:745`, `UiAudit.cpp`) — пользовательские темы добавлять **после** 15 встроенных.

## 4. Цветовые литералы вне темы

Грубая статистика по `src/` без тестов, selftest и `*.gen.h` (грепом по строкам):
- `IM_COL32` 119 строк, `ImVec4(` 238, `ImColor` 20 → **377 строк**.
- Чисто числовые литералы (`IM_COL32(r,g,b[,a])`, `ImVec4(f,f,f,f)`): **78 строк**, из них 34 — прозрачный/нулевой цвет (не тема).
  Это ~44 «настоящих» захардкоженных цвета.
- Остальные ~283 строки: производные и альфы (`ImVec4(accent.x*0.82f…)`, `Theme.cpp:121,158-161`), градиенты заставки
  (`core/SplashScreen.h:142-255` — фирменная графика, оставить фиксированной), а также `ImVec4(` как вектора/размеры
  не-цвета (доля **не оценена**). Производные от цветов темы темизируются сами и переводу не подлежат.

Настоящие литералы по файлам (убывание): `panels/PerfPanel.cpp` 10, `ui/design/components/FormParts.h` 8,
`components/FieldWell.h` 8, `bodies/FieldParams.cpp` 7, `frame/StageNodeBodies.cpp` 6, `components/MenuParts.h` 4,
`TopBarParts.h` 3, `LibraryParts.h` 3, `panels/ArrangePanel.cpp` 3, `bodies/PreviewBodies.cpp` 3, далее по 2
(`ToolCursor.h`, `DialogParts.h`, `ModMatrixPanel.cpp`, `StageMenuBar.cpp`). Хвост — по 1.

**Скрытая проблема, важнее литералов:** уже вынесенные в `tok::pal::c_…` 605 использований (587 разных значений) *выглядят* токенами,
но семантики не имеют. Для полноценной темизации их надо группировать в роли (`pal::c_3B82F6FF` → `accent.info` и т.п.).

Оценка перевода (грубо, не проверено правкой): 44 литерала → новые роли в `tokens.json` — **S–M** (полдня);
сведение 587 хекс-имён в ~60-100 ролей с переименованием 1288 использований (605+160 pal/palf + повторы) — **L**,
механизируется скриптом-переименователем, но роли придумываются вручную по контексту использования.

## 5. Удобство редактирования

- **Горячая перезагрузка:** файлового вотчера в проекте нет. Есть образец опроса mtime — `core/AssetCache.h:39,62`
  (`std::filesystem::last_write_time`). Достаточно опроса раз в ~0.5 с активного файла темы в главном цикле → при смене
  mtime: перечитать, `tok::ResetToDefaults()` + применить, `ApplyTheme()` (вызывается из `app/Startup.cpp:1678`,
  `panels/SettingsWindow.cpp:230,256,336`). Токены читаются покадрово, поэтому остальное подхватится само (**не проверено**).
- **Экспорт встроенной темы** как образец: «Сохранить текущую как JSON» в Settings — сериализует `colors`, `categories`,
  `cables` и все `tokens` из реестра (значения активного режима) с комментарием-шапкой в поле `_doc`. JSON комментариев не
  поддерживает → использовать ключи `_doc`; в загрузчике игнорировать ключи с `_`.
- **Валидация и ошибки:** парсинг `nlohmann::json` в try/catch; сообщения «файл:строка» не получится из коробки (`parse_error.byte`
  → пересчитать в строку вручную); неверный цвет/неизвестный токен — строка в лог + список в Settings под выбором темы, тема
  применяется «насколько получилось». Битая тема не должна ронять запуск — откат на `base`/Ember.
- **Документация имён токенов:** сейчас описаний нет. Добавить в `tokens.json` необязательное поле `doc` к ролям (формат
  пары сейчас `{dark, light}` — расширяется без поломки генератора) и генерировать из `build_tokens.py` файл
  `docs/theme-tokens.md` (имя, тип, дефолт dark/light, описание); та же таблица может открываться кнопкой в Settings.
  Для 786 хекс-палитровых токенов описание появится только после их превращения в роли (этап в).
- Контраст: авто-подтяжка текста до 4.5:1 (`Presets()`) применять и к пользовательским темам; для токенов-переопределений не применять.

## План по этапам

**(а) Минимум: JSON-темы с 6 базовыми цветами + горячая перезагрузка — M**
- Файлы: `core/CategoryColors.cpp/.h` (`Presets()` из статического `const` в перезагружаемый, загрузчик JSON, поддержка `base`/`categories`/`cables`),
  `panels/SettingsWindow.cpp` (список, «Экспорт текущей», «Открыть папку тем», вывод ошибок), главный цикл/`app/Startup.cpp` (опрос mtime).
- Результат: файл из 6 цветов — валидная тема; правка файла видна сразу; `ApplyTheme()` покрывает ~61 `ImGuiCol_*`.
- Риски: `Presets()` — статика, на неё завязаны тесты по индексам (`MiscTests.cpp:745`, `UiAudit.cpp`); режим плагина с отдельным `SettingsDir`;
  взаимодействие с `Infinite.appearance`; светлая/тёмная по яркости. Токены `tokens.json` темой ещё не управляются.

**(б) Переопределение токенов из JSON — M**
- Файлы: `tools/design/build_tokens.py` (inline-переменные, дефолты, реестр, генерация `docs/theme-tokens.md`),
  `app/ui/design/TokenColors.h` (без изменений вызовов), `app/AppShared.h:2287` (`kPredictionPinCol`), загрузчик из этапа (а),
  `ui/Theme.cpp` (секция `imgui` после вывода), `tokens.json` (поля `doc`).
- Результат: `tokens`/`imgui`/`palette` в теме; 71 именованная роль управляемы по именам, палитра — по хексу.
- Риски: генератор и `--check` в CI/сборке; `inline` вместо `constexpr` (скорость — не измерялась); `palette`-переопределение
  по хексу зацепляет все несвязанные использования; `TerminalPanel.cpp:84` (указатели) должен остаться рабочим.

**(в) Литералы → токены — L (можно дробить)**
- Часть 1 (S–M): ~44 «настоящих» литерала → новые роли; файлы из §4 (PerfPanel, FormParts, FieldWell, FieldParams, StageNodeBodies, …).
- Часть 2 (L): 587 хекс-палитровых значений → семантические роли, скрипт-переименование ~1300 использований в десятках файлов
  (ChatPanel, ArrangePanel, ModWidgets…); визуальный регресс без скриншот-тестов не отловить.
- Риски: переименование массовое → конфликты с параллельной работой других этапов (инспектор трогает `Stage*.cpp`, `ParamWidgets.cpp`);
  делать между этапами, не одновременно; заставка (`SplashScreen.h`) — осознанно фиксированная.

## Не проверено
Всё, что про поведение: что токены читаются покадрово без кэшей; отсутствие `switch`/`template` по цветовым токенам;
что `inline`-переменные не сказываются на скорости; как `Infinite.appearance` ложится поверх `base`; доля цветов среди
283 «производных» строк `ImVec4(`; точное число правок при переименовании палитры.
