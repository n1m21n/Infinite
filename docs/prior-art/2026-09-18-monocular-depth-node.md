## Patterns across sources
- Depth Anything V2 has functionally replaced MiDaS as the default in creative/real-time tools (TouchDesigner, ComfyUI, browser/WebGPU demos) — MiDaS plugins are legacy, not actively recommended new work.
- **Only the Small variant is commercially safe.** Base/Large/Giant carry CC-BY-NC-4.0 (non-commercial only), which is a hard no for a shipped product. This is the single most important licensing fact and it is easy to miss if you just grab "Depth Anything V2" without checking the specific HF card per size.
- The `onnx-community` org on Hugging Face is the standard place the JS/ONNX ecosystem gets pre-exported vision models; their Depth Anything V2 Small repo explicitly carries `license: apache-2.0` in its model card metadata (verified via HF API, not scraped text).
- Measured file sizes (verified via HTTP HEAD against the actual files, Sept 18 2026):
  - `onnx/model.onnx` (fp32): 99,060,839 bytes ≈ **94.5 MB**
  - `onnx/model_fp16.onnx`: 49,642,442 bytes ≈ **47.3 MB**
  - `onnx/model_quantized.onnx` (int8): 27,258,801 bytes ≈ **26.0 MB**
- Output: Depth Anything (V1 and V2) outputs **relative inverse depth** (higher value = closer), not metric depth. Standard post-processing (used by both the HF pipeline and Infinite's own `SubjectMaskOnnx` precedent) is a simple min-max normalize of the raw float map to [0,1], then to a grayscale byte texture — no metric calibration needed, exactly the pattern already coded in `SubjectMaskOnnx.cpp`.
- Known cross-platform pain point: ONNX Runtime's CoreML EP has an opset ceiling and silently CPU-falls-back subgraphs above it, with no error surfaced. Depth Anything V2's export (opset 18, ViT/DINOv2 backbone with attention blocks) sits close to that ceiling. This doesn't block correctness (CPU fallback still runs, same as Infinite's own matting node does today), but it does mean "GPU-accelerated on Mac" should not be assumed without testing — CPU EP should be the baseline assumption everywhere, matching how `SubjectMaskOnnx` already treats Windows/Linux as CPU-or-DirectML and Mac as a separate non-ONNX path.

## Recommendation
**Model:** Depth Anything V2, **Small** variant only (24.8M params, Apache-2.0 — this is the only size safe for a commercial product; Base/Large/Giant are CC-BY-NC-4.0, non-commercial).

**ONNX source:** [`onnx-community/depth-anything-v2-small`](https://huggingface.co/onnx-community/depth-anything-v2-small) on Hugging Face. Use `onnx/model_fp16.onnx` (≈47 MB) as the shipped model — good size/quality tradeoff, half the fp32 size with negligible quality loss; fall back to `onnx/model_quantized.onnx` (≈26 MB) if app size is a bigger concern than the last bit of quality.

**Why this and not the alternatives:**
- MiDaS: older, superseded as the de facto default in exactly this tool category (TouchDesigner/creative-coding communities have moved on); more model variants to choose between, more decision surface for a non-expert.
- Depth Anything V1: superseded by V2 (better quality, same license structure, same ecosystem support).
- ZoeDepth / Marigold / UniDepth / Metric3D: metric-depth or diffusion-based models — heavier, slower (Marigold is diffusion-based, multi-second per frame, wrong category entirely for "real-time-ish"), and not the community default for this use case.
- Depth Anything V2 Base/Large/Giant: better quality but CC-BY-NC-4.0 — legally unusable in a product Infinite ships and sells/distributes.

**Implementation path:** mirror `src/platform/common/SubjectMaskOnnx.cpp` exactly — same `Ort::Session` setup, same CHW float + ImageNet mean/std normalization on input, and the exact same min-max-normalize-to-grayscale pattern already written there for postprocessing (Depth Anything's raw output is relative inverse depth, same "normalize to [0,1] then to byte texture" shape as the existing matting mask). Given there is no macOS Vision-framework depth equivalent, this node should run through ONNX Runtime on all three OSes (CPU EP as the safe baseline; DirectML on Windows and CoreML EP on Mac as opportunistic GPU paths, same optionality the existing `ProviderHook` in `SubjectMaskOnnx.h` already provides) rather than the per-OS split the matting node uses.

## Open questions
- Exact CPU/GPU inference time for this specific export on M-series Mac / mid-range Windows GPU was not independently benchmarked here (no local run performed); TouchDesigner community posts report real-time (interactive, well under 1s/frame) performance for Depth Anything V2 Small on both Mac and PC, but that is their pipeline, not a direct benchmark of the `onnx-community` fp16 file.
- Whether Infinite wants a fixed input resolution or Depth Anything V2's native dynamic-shape input (the HF preprocessor config lookup did not resolve in this session — worth confirming input H/W handling the same way `SubjectMaskOnnx.cpp` already does, by reading shape[2]/shape[3] from the loaded session rather than hardcoding).
