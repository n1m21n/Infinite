## Cause found in the code (2026-10-29)
Every voice and effect is a random knob draw: `Seeded()` in `SampleStyles.cpp` sets about 35% of a node's knobs (variation 0.5) to a uniform
value across the whole range (log-uniform for frequencies), then picks 1-3 effects from the card (Reverb, Audio Filter, Drive, Saturator ...)
with knobs drawn the same way. A cutoff drawn log-uniform over 20 Hz-20 kHz lands under 1 kHz about half the time (dark); random Drive and
Saturator amounts distort; stacked random effects smear (muddy). No part has a designed sound: that is why leads are not massive, toms sound
like bass and textures sound like grumbly bass.

Data already on disk and barely used: Groove MIDI (1,150 files, drummer-labelled genres: rock 281, hip-hop 91, funk 77, punk 58, New Orleans
funk 48, jazz 46, Afro-Cuban, Brazilian, reggae ...) gives 916 accepted bars today, because `public_drums.py` reads only 2 bars per file
(`--per-file 2`; the performances run dozens of bars) and keeps hits as x/. with velocity and timing dropped. Chords are not a gate loss:
the 11,700 files are 965 distinct progressions, each copied into many keys, so more harmony needs a new source (Chordonomicon, POP909 chords).

## Found while measuring (2026-10-29): every part but synths, bass and textures was silent
The master's 30 Hz high-pass (WIP b1cfb419) wrote its filter type as `i type 4`. Effect params are floats, so the reader
looks for `f type`, never finds it and keeps the default: a 24 dB low-pass at 30 Hz on the whole loop. Pads, keys,
leads, drums and the rest came out near -100 dBFS and failed the master's loudness gate on every redraw; synths, bass
and textures passed only as a 40-80 Hz sine. The live website wasm predates that commit and is not affected. Fixed
(`f type`), plus the same slip on three FX band-passes and the master filter's unpinned knobs (Add() draws any knob
left out; a drawn envAmount sweeps the cutoff). Delays set by hand now turn `sync` off: with it on, `timeMs` is ignored.
