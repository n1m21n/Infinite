# P2.5 — Flip the transport clock to sample-accurate

Goal: `Transport` currently advances by wall-clock delta once per render
frame (`Transport::Tick`, called from the main loop). Make the audio
engine's sample counter the source of truth for `Beats()`/`Seconds()`
whenever it's running, with the existing frame-driven `Tick()` path
becoming the fallback for when it isn't (no device, or it failed to open).
This is a small, surgical phase — one file's internals change
(`src/core/Transport.h`/`.cpp`), plus two call sites in `AudioEngine`. It
must land before P3a: note scheduling needs a clock that's safe to read
from the audio thread with sample-accurate position, not a value that only
updates once per ~16ms render frame and was never meant to be touched from
another thread.

**Clean-room rule, verbatim:** do not open, read, grep, or reference
`/Users/namansoni/BespokeSynth`.

## Design — resolved, not left open

**One signal decides which clock source `Beats()`/`Seconds()` trust:
whether the audio sample rate is known.** No separate "audio driven" bool
to keep in sync with it — `mAudioSampleRate > 0.0` *is* "the engine is
open and its sample counter is live." This collapses what would otherwise
be two flags that could disagree into one.

`Transport.h` additions:
```cpp
// Called once, main thread, immediately after AudioEngine::Instance().Start()
// succeeds. Captures the current frame-driven position as the audio clock's
// starting offset, so the switch is seamless - no jump at the exact moment
// this phase's build lands and the engine starts producing real callbacks.
void NotifyAudioEngineStarted(double sampleRate);

// Called once, main thread, immediately after AudioEngine::Instance().Stop().
// Freezes mBeats/mSeconds at the audio clock's last live value so Tick()'s
// fallback path continues from exactly where the audio clock left off.
void NotifyAudioEngineStopped();

// Called from the real-time audio thread, once per AudioEngine::Process
// callback, before any node in that block reads Beats()/Seconds(). Adds
// numFrames to the sample counter only while playing - this is what makes
// pause freeze the audio-driven clock the same way it already freezes the
// frame-driven one.
void AdvanceAudioClock(int numFrames);
```

Every field `AdvanceAudioClock`/`Beats`/`Seconds` touch becomes atomic,
since those three can now be called from the audio thread while `Tick`/
`SetTempo`/etc. are called from the main thread, concurrently:
```cpp
std::atomic<bool> mPlaying { true };            // was plain bool
std::atomic<float> mBpm { 120.0f };              // was plain float
std::atomic<uint64_t> mAudioSampleCounter { 0 };
std::atomic<double> mAudioSampleRate { 0.0 };    // 0 = fallback mode
std::atomic<double> mAudioBeatsOffset { 0.0 };
std::atomic<double> mAudioSecondsOffset { 0.0 };
```
`mBeats`/`mSeconds` themselves **stay plain `double`, not atomic** — they
are only ever touched by `Tick()`, which only runs on the main thread and
only writes them while `mAudioSampleRate == 0` (fallback mode); the audio
thread never reads or writes them, so they don't need to be. Getting this
split right (which fields cross threads vs. which stay main-thread-only)
is the actual point of this phase — don't reach for `std::mutex` here, the
whole design is atomics-only per the audio-thread rules P1 already
established.

`Seconds()`/`Beats()` (`memory_order_relaxed` throughout — this is a
polling clock read, not a handoff that needs acquire/release ordering
anywhere):
```cpp
double Transport::Seconds() const
{
   const double sr = mAudioSampleRate.load(std::memory_order_relaxed);
   if (sr > 0.0)
      return mAudioSecondsOffset.load(std::memory_order_relaxed) +
             (double)mAudioSampleCounter.load(std::memory_order_relaxed) / sr;
   return mSeconds;
}

double Transport::Beats() const
{
   const double sr = mAudioSampleRate.load(std::memory_order_relaxed);
   if (sr <= 0.0)
      return mBeats;
   const double secOffset = mAudioSecondsOffset.load(std::memory_order_relaxed);
   return mAudioBeatsOffset.load(std::memory_order_relaxed) +
          (Seconds() - secOffset) * (mBpm.load(std::memory_order_relaxed) / 60.0);
}
```
Both are then safe to call from **either** thread at **any** time — no
dependency on `Tick()` having run this frame, which matters because the
audio thread's block rate (~93 callbacks/sec at the P0-measured ~470-frame
blocks) has nothing to do with the render frame rate `Tick()` is driven
by, and P3a's note scheduling will call `Beats()` from inside
`ProcessBlock`.

`Tick()` becomes exactly what the plan calls it — the engine-stopped
fallback:
```cpp
void Transport::Tick(float deltaSeconds)
{
   if (deltaSeconds > 0.25f)
      deltaSeconds = 0.25f;

   // unchanged: external-clock-freshness aging runs regardless of mode
   if (mExternalSync && mExternalClockFresh) { /* ...as today... */ }

   if (mAudioSampleRate.load(std::memory_order_relaxed) > 0.0)
      return; // audio-driven: Beats()/Seconds() compute live, nothing to accumulate here

   if (!mPlaying.load(std::memory_order_relaxed))
      return;
   mSeconds += deltaSeconds;
   mBeats += deltaSeconds * (mBpm.load(std::memory_order_relaxed) / 60.0);
}
```

`NotifyAudioEngineStarted`/`NotifyAudioEngineStopped` implementation —
order matters in both, publish `mAudioSampleRate` **last** in Started (so
no reader can observe a live sample rate before the offsets it depends on
are set) and **first** in Stopped's inverse (capture the live value before
switching back to fallback, not after):
```cpp
void Transport::NotifyAudioEngineStarted(double sampleRate)
{
   mAudioSecondsOffset.store(mSeconds, std::memory_order_relaxed);
   mAudioBeatsOffset.store(mBeats, std::memory_order_relaxed);
   mAudioSampleCounter.store(0, std::memory_order_relaxed);
   mAudioSampleRate.store(sampleRate, std::memory_order_relaxed); // publish last
}

void Transport::NotifyAudioEngineStopped()
{
   mSeconds = Seconds(); // read the still-live audio-driven value...
   mBeats = Beats();
   mAudioSampleRate.store(0.0, std::memory_order_relaxed); // ...then switch back to fallback
}
```
`AdvanceAudioClock`:
```cpp
void Transport::AdvanceAudioClock(int numFrames)
{
   if (mPlaying.load(std::memory_order_relaxed))
      mAudioSampleCounter.fetch_add((uint64_t)numFrames, std::memory_order_relaxed);
}
```

`Rewind()` needs one addition: it currently zeroes `mBeats`/`mSeconds`
only, which does nothing visible while audio-driven (those fields aren't
being read in that mode). Also reset `mAudioSampleCounter` and both
offsets to `0`:
```cpp
void Rewind()
{
   mBeats = 0.0;
   mSeconds = 0.0;
   mAudioSampleCounter.store(0, std::memory_order_relaxed);
   mAudioBeatsOffset.store(0.0, std::memory_order_relaxed);
   mAudioSecondsOffset.store(0.0, std::memory_order_relaxed);
}
```
This can race a concurrent in-flight `AdvanceAudioClock` fetch_add from
the audio thread (rewind called from the main thread at the same instant a
callback is running) — worst case is one block's worth (~10ms) of position
error on the sample a rewind lands on, which is inaudible and not worth
a lock for. Say so in a comment next to `Rewind()` rather than leaving it
unexplained if someone goes looking for why this isn't perfectly atomic
across the three stores.

## Wiring into `AudioEngine`

- `src/audio/AudioEngine.cpp`, `Start()` (currently `:34-41`): on success,
  after `mSampleRate.store(sampleRate, ...)`, call
  `Transport::Instance().NotifyAudioEngineStarted(sampleRate)`. Needs
  `#include "core/Transport.h"` — check the actual relative include path
  other `src/audio/` files use for `src/core` headers (this codebase's
  `target_include_directories` already lists `src/core` as a bare include
  root per `CMakeLists.txt:107-112`, so `#include "Transport.h"` without a
  `core/` prefix is likely correct — confirm against how an existing
  `src/audio/*.cpp` already includes something from `src/platform`
  (`AudioEngine.cpp` already does `#include "platform/Platform.h"` at
  `:5` — note that one *does* use a directory prefix, so check whether
  `Transport.h` needs the same or not before assuming; the include layout
  isn't perfectly uniform across this codebase, verify rather than guess).
- `Stop()` (`:43-46`): call `Transport::Instance().NotifyAudioEngineStopped()`
  before or after `Platform::AudioDeviceClose()` — after is slightly safer
  (no more callbacks can fire once the device is closed, so nothing can
  race the notify), prefer that order.
- `Process()` (`:90-129`): call `Transport::Instance().AdvanceAudioClock(numFrames)`
  once per callback, after the FTZ/DAZ guard and before the node-processing
  loop — so any node whose `ProcessBlock` this callback runs (once P3a adds
  note-scheduling nodes) sees the position already advanced for *this*
  block, not last block's.

## What this phase does not need to do

- No new `INode`/node-editor work — this doesn't touch `main.cpp`'s
  wiring/cable code from P2 at all, only the two `AudioEngine::Instance()`
  call sites and `Transport` itself.
- No UI for showing "audio-driven vs. fallback" mode — nothing user-facing
  changes; this is purely an internal precision/thread-safety upgrade. If
  you want a cheap sanity signal for testing (see below), a `printf` in a
  test fixture is enough, don't add persistent UI for it.
- Sample-accurate note scheduling itself (reading `Beats()` inside a note
  node's `ProcessBlock` to decide exactly which sample within the block a
  note lands on) is P3a's job — this phase only makes `Beats()` safe and
  correct to call that way, it doesn't add any caller that does yet.
