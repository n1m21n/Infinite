# 3.2 Field material domain (waiting for owner)

Gate (PLAN 3.2): a hand-written Field material equals the same Material set by knobs within 0.01 FLIP.
Unblocks 3.3 library use in 3D, 3.4 lowering, 3.7 recipes. 3.1 (MSL backend) is its prerequisite and needs no
approval, so it is built first.

## What the user sees

```
 Field Pixel  [Domain: Image | Material]          Material
   code ───────────────────────────────► field ─► (knobs stay; a wired field output overrides its knob)
```

| Decision | Choice | Why |
|---|---|---|
| Where the code lives | Field Pixel gets a Domain choice `Material` (no new node) | the Field family already has the editor, presets, errors; a new node would duplicate them |
| How it reaches the surface | Material gets one input, `field` | one cable; knobs keep working for everything the program does not write |
| What a wired output does | replaces that knob's value per hit | same mental model as plugging an image into a map slot |
| Preview in the Field Pixel body | the program on a lit sphere | an image of a 3D function needs a shape |

## The domain

| Inputs (read-only names) | Meaning |
|---|---|
| `P`, `Pobj` | world / object position |
| `N`, `Ng` | shading / geometric normal |
| `UV`, `T` | first UV set, tangent |
| `curv`, `ao` | pointiness (mesh, per vertex) and baked AO where available, else 1 |
| `facing`, `backface` | dot(N, V), 1 on back faces |
| `objRand`, `islandRand` | per object and per UV island random 0..1 |
| `attr(name)` | named mesh attribute |
| `time`, `beat` | as in every Field domain |

| Outputs (any subset) | Maps to MatRec |
|---|---|
| `base` (vec3), `rough`, `metal`, `emission` (vec3) | base, roughness, metallic, emission |
| `height` | bump normal (raster/live: screen derivatives; settle: finite difference of three evaluations) |
| `normal` (vec3, tangent space) | normal map path |
| `mask` | opacity (alpha test, as `mapOpacity`) |

Rate is inferred as in every domain (bare names, no `@`); `param` knobs become node knobs as today.

## Engine side

- The compiler emits one function `void fieldMat(in FieldIn i, inout FieldOut o)` in the GLSL/MSL subset;
  it is spliced after the shading headers (L2 ordering) into the raster program and the Metal library, keyed by
  the program hash so an edit recompiles only that pipeline variant.
- MatRec gains `fieldId` (0 none); the shader calls `fieldMat` only when it is set, so plain materials cost nothing.
- A failed compile is the node error (1.2), and the material falls back to its knobs.

## Not in scope

Multiple Field materials per scene beyond 8 variants (compile cost), volume and displacement outputs (4.1, 4.5).

## Ask

Approve: the `Material` Domain on Field Pixel and the `field` input on Material.
