# 7.3 Render passes as Render 3D outputs (waiting for owner)

## Today

| Where | What |
|---|---|
| Render 3D | one image pin: the beauty (`GetOutputTexture()`) |
| INode | `GetOutputTexture(int index)` already exists (Field Pixel's aux state uses it); ImageCable pulls by index |
| Metal live | MRT already writes normal + eye distance (`mNz`, RGBA32F, denoiser guide) |
| Metal settle | first-hit albedo (`mPtAux`) and normal + distance (`mPtGd`) already written for the denoiser |
| GL raster | beauty only |

So depth, normal and albedo exist on the Metal side as private guides. Nothing reaches a cable.

## Proposal

```
 Render 3D ──► image        (beauty, pin 0, unchanged)
           ├─► depth        linear eye distance, 0..1 over near..far of the scene bounds
           ├─► normal       world normal * 0.5 + 0.5
           ├─► albedo       first-hit base colour (linear)
           ├─► mask         layer mask: white where the chosen Material/object is visible
           └─► id           object id as a flat hashed colour (one colour per instance group)
```

| Pass | R (GL raster) | L (Metal live) | T (Metal settle) |
|---|---|---|---|
| depth | extra MRT target in the forward pass | from `mNz.w` | from `mPtGd.w` (first hit) |
| normal | extra MRT target | from `mNz.xyz` | from `mPtGd.xyz` |
| albedo | extra MRT target (base x maps) | new MRT target (4 colour targets used today: 5th) | from `mPtAux.rgb / coverage` |
| mask | extra MRT target, 1 where the instance carries the chosen mask tag (new per-instance int) | same, one float in the 5th target's alpha | first hit, accumulated (anti-aliased) |
| id | extra MRT target, `CopyRandom(copyGroup)` colour | same | first hit, nearest (no blend) |

- Pins appear only when the `Passes` toggle on Render 3D is on (one checkbox, no sub-text). Off: the node draws
  exactly as today, no extra targets, no cost. Old patches load with it off.
- Passes are written in the same pass as the beauty (MRT), never a second render. One RGBA16F target carries
  albedo + mask; depth + normal reuse the existing guide target. id goes in an RGBA8 target.
- Pass textures are GL textures shared with Metal the same way the beauty is (IOSurface), so downstream nodes read
  them like any image.
- Export: the movie export stays beauty only. A pass is exported by cabling it to its own Output, as with any image.
- `mask` picks its target by a `Mask` dropdown on Render 3D listing the connected Materials (and `Selected object`);
  no new node.
- Anti-aliasing: depth, normal and id are nearest (first sample); albedo and mask are averaged with the beauty.

## Cost

| Item | Estimate |
|---|---|
| GL raster | +2 colour targets at 1080p: ~16 MB, a few % fill |
| Metal live | +1 target (albedo/mask) + 1 RGBA8 (id) at 1080p: ~24 MB; depth/normal free |
| Metal settle | free: the guides exist; id/mask need one more first-hit write |
| Code | Render3DNode outputs + toggle + save/load; one MRT target per engine; ~400 lines |

## Checks when built

- A/B: with `Passes` off, every sweep case pixel-identical (`sweep.py same`) on R, L, T.
- With it on: depth/normal/albedo of `cornell` match Blender's Z, Normal and Diffuse Color passes (Blender renders
  them in the truth run); MAE under 0.02 after the same 0..1 mapping.
- id stays stable across frames for an animated scatter (same colour per copy group).

## Decisions taken (owner may overturn)

- Five passes, not Cycles' full list: these are the ones compositing patches ask for (depth of field, relighting,
  masking, matte by object). Shadow, AO, emission, cryptomatte stay out.
- One toggle shows all five pins rather than a per-pass checklist.
- Depth is normalised to 0..1 over the scene bounds so it reads as an image without a Map Range.

## Ask

Approve five new image outputs on Render 3D behind one `Passes` toggle.
