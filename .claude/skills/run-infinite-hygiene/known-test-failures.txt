VIDEOAUDIOTEST|"VIDEOAUDIOTEST FAIL - BUG" while the tone check itself reports TONE PRESENT — the failing leg is durationOk, not the audio content: `sVaRecordedFrames` is sampled from `OutputNode::RecordedFrames()` synchronously at the `StopRecording()` call site (src/main.cpp, INFINITE_VIDEOAUDIOTEST block, frameId==62), but `StopRecording()` itself blocks until AVAssetWriter finishes flushing whatever frames were still in flight, so the file's actual encoded length ("recorded 39 frames, status: saved 56 frames" in one run) ends up longer than the counter captured moments before the flush. `expectedDuration` is derived from the stale 39-frame count, so it disagrees with the real ~56-frame/1.87s file by more than the 0.3s tolerance. None of the commits between v0.4.25 and this release touch OutputNode/recording/video code (comb-filter EQ, Sampler loop crossfade, Metallic level calibration, Analog oscillator, auto-instance-numbering) — this is a pre-existing race between the in-flight frame counter and the async flush, not a regression from this release's changes.
