# Known baseline failures

Inherited from the macOS hygiene driver. These checks report FAIL by design or because the generic sweep rig cannot observe the param (no sample loaded, gated by a sibling default, effect longer than the probe window, ...). They are not regressions unless the list changes.

Windows note: PLUGINSCANTEST (Audio Units) was dropped. Since 0.58 DRAGTEST, SAMPLERDRAGTEST, MEDIADRAGTEST, PLUGINDRAGTEST and AUDIORECOVERYTEST are expected to pass, and AUDIOPARAMSWEEPTEST must no longer crash in Clip Matrix. All of them failed on 0.57 for test-side or headless reasons, not regressions.

- known baseline (not a regression unless it changes): PHASE1TEST is occasionally flaky on particle-system timing; rerun once before treating it as a regression. PHASEATEST currently fails on a pre-existing "Smooth" node- name collision unrelated to audio work — see the spawned task to fix it.

- Turbo 0.70: **AUDIOPARAMSWEEPTEST and ROUNDTRIPTEST pass - no known FAILs left.** The sweep rig now registers its note consumer before the held note (synths used to run silent), watches a window of blocks, a note-off, a running transport, an input step (attack / release / lookahead), a cube on geometry pins and worker-thread changes (EffectParamDef::asyncSettle), and feeds each extra pin its own tone. What it still cannot drive headless is reported SKIP with the reason, never pass: a node where no param moves the output ("idle in the generic rig": sample / plugin / content players such as Drum Sequencer, MPC, Sampler, Granular), and params declared with EffectParamDef::skipReason (sensors, export settings, recorded content, the global transport). ROUNDTRIPTEST accepts on paste only the values a paste re-derives by design (Drum Sequencer trims clamped into range, a pasted Looper's own loop id / file). The sweep found one real bug on the way: MasterChain::TimeCoef floored every time at 10 ms (Super Mixer compressor attack).

- known baseline: Chorus/Flanger/Phaser/Stutter/Tremolo's sync param used to be baselined alongside rateDiv here too, but is no longer — each kernel's synced-vs-free rateHz/period default now differs enough (e.g. ChorusKernel: 0.5Hz free vs 2Hz synced quarter-note) that toggling sync alone is observable within the sweep's window. rateDiv still fails: EffectDefs.cpp gives it no {sync, 1.0f} prerequisite, so for these five (sync defaults false) it's probed with the sync branch dead - the same gated-param blind spot as Audio Filter's gain. Delay itself still fails both sync and rateDiv per the paragraph above (no kernel-timing escape hatch there).
